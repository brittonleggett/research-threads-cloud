# 04_DATA — where corpus information lives (EMPIRICAL Data Center paper)

**Rule:** a fact about a case belongs in a CSV here. `notes\` holds the narrative of what a session did, and nothing found only in a note counts as collected.

| File | What it is | Who writes it |
|---|---|---|
| `corpus_inventory.csv` | **The corpus of record.** One row per case entry; its row count is the N the paper reports. | Interactive sessions only, after verification. Nightly runs never add or delete rows here. |
| `candidate_leads.csv` | Living list of every lead not yet in the corpus, with its source level and status. | Nightly runs APPEND rows here. Any session may update status. |
| `watchlist.csv` | Pending items (court rulings, scheduled votes), each with a `next_check` date. | Any session. Do not re-check an item before its `next_check`; this stops the nightly "still no ruling" loop. |
| `verification_YYYY-MM-DD\` | Fetch receipts from a verification pass: URL, fetch result, verbatim receipt quote, verdict. | The verification pass that made them. |
| `url_ignore.txt` | URLs in notes that are not leads: literature, tools, background. One per line, with a `# reason`. | Any session. |
| `candidate_leads_inventory_2026-10-02.csv` | A one-time snapshot extracted from all notes on 2026-10-02. Superseded by `candidate_leads.csv`; keep it for provenance. | Frozen. |

## Inclusion rule (approved by Britton 2026-10-02)
A case enters `corpus_inventory.csv` when it is a 2025–26 U.S. local or state data-center siting dispute AND at least one case-specific source was actually fetched and read (news or official record), with a verbatim receipt quote in a `verification_*` file. Leads backed only by a WebSearch summary, and rows that exist only on a tracker list, stay in `candidate_leads.csv`.

## How a lead moves
1. Found: append it to `candidate_leads.csv` with `status=CANDIDATE` and the most specific `source_level` you can honestly assign.
2. Verified: the fetch receipt goes into a `verification_*` file. Then set `status=READY` in `candidate_leads.csv`.
3. Added: an interactive session copies it into `corpus_inventory.csv` with a new corpus_no and sets `status=ADDED (#n)`.
4. Rejected: set `status=REJECTED` with the reason (out of scope, fabricated identifier, contradicted by its source).

## Closing check for every session that writes notes
Run from the repo root: `python tools/check_leads_captured.py DATA_CENTER_PAPER --since <today>`. It must print `UNCAPTURED: 0`. Every URL your note mentions must sit in a 04_DATA CSV or in `url_ignore.txt`.

## Never
- Never invent or complete a URL, case number, vote count or date. Fabricated case numbers have already been caught twice: "26SL-CC03024" and "ECU004457".
- Never put copyrighted article text or PDFs here; the repo mirror is public.
